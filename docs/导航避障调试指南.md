# 导航避障调试指南

> 适用对象：`srm27_nav_27` 的 Nav2 避障链路（感知 → 代价地图 → 全局规划 → 局部控制器 → 恢复行为）。
> 速度相关的参数（限速、加速度、前瞻、PID）见 [`导航速度调试指南.md`](./导航速度调试指南.md)。
> 文中数值为当前参数文件里的实际值；部分注释已过期，见 §11。

---

## 0. 先分清两套完全不同的避障语义

这决定了"想让它躲得好一点"到底该改哪里——**Omni 和 MINCO 的可调项几乎不重叠**。

| | **Omni PID**（`nav2_params_srm.yaml`） | **MINCO-MPC**（`*_minco.yaml`） |
|---|---|---|
| 局部路径 | 全局路径截断到局部代价地图，**只在 10 个采样点上**做碰撞检查 | 后端在 ESDF 上做连续净空优化 + 硬校验 |
| 判据 | 二值：任一点 `cost ≥ 253`（`INSCRIBED_INFLATED_OBSTACLE`）即抛异常 | 连续：全轨迹净空 ≥ `robot_radius + clearance_margin` = **0.38 m** |
| 用不用代价梯度 | **不用**。`inflation_radius` 产生的 1~252 代价对控制器毫无影响 | **不用**。快照里只有 `LETHAL(254)` 是障碍种子 |
| 失败的现场表现 | `Collision detected in the trajectory` → 行为树清局部代价地图、`FollowPath` 重试 10 次 → 再失败进 recovery | 候选轨迹被校验器整条丢弃 → 输出零速 → 10 s 后被进度检查器判 `Failed to make progress` → recovery 拖车 |
| 提速/贴墙时最该看的项 | 代价地图 `robot_radius`、`resolution`、体素层参数；全局规划 `w_traversal_cost` | `safety.robot_radius` / `clearance_margin` / `minco.w_obstacle` / `planning_horizon`，且**代价地图 `robot_radius` 必须 ≥ 0.38** |

> `inflation_layer` 在这套栈里的真正作用只有一个：**塑造全局路径的形状**（Theta* 用代价平方做通行费）。
> 它不会让任何控制器减速——两个控制器都没有"接近障碍时减速"的逻辑。

## 1. 避障数据流

```text
MID-360 点云 ─┬─► point_lio ─► 里程计 / 配准点云（定位）
              │
              ├─► terrain_analysis      ─terrain_map─┬─► local_costmap.intensity_voxel_layer ─┐
              │   （近距，5 m）                        │   + static_layer + inflation_layer    │
              └─► terrain_analysis_ext  ─terrain_map_ext─► global_costmap.intensity_voxel_layer┤
                  （远距，10 m）                        │                                       │
                                                        └─► Theta* 全局规划 ─► 局部路径 ─► FollowPath 控制器 ─► 速度
                                                                                   │
                                                              碰撞检查/校验失败 ───┴─► 行为树 recovery（清代价地图 → BackUpFreeSpace）

pointcloud_to_laserscan ─► obstacle_scan ─► slam_toolbox（**仅建图模式**，不参与避障）
```

**障碍只有一条来源：`terrain_analysis` / `terrain_analysis_ext` 发布的地形点云。**
没有独立的激光障碍层、没有动态障碍层、没有代价地图外的感知输入。

## 2. 感知层：地形分析与点云（`terrain_analysis` / `terrain_analysis_ext`）

参数位置：四份 `nav2_params_srm*.yaml` 的 `terrain_analysis` / `terrain_analysis_ext` 段。
两侧数值基本一致，个别项不同（下表"实车/仿真"列已标）。

| 参数 | 近距(local) | 远距(ext) | 作用与调参后果 |
|---|---|---|---|
| `vehicleHeight` | 0.5 | 1.0 | 车辆高度阈值，用于判断哪些点算"可通过的地形"而不是障碍。调大 → 更多低矮物体被当成可压过的地形（**漏检**）；调小 → 更保守，容易被地面噪声/坡面判成障碍 |
| `minRelZ` / `maxRelZ` | -1.5 / **0.5** | -1.5 / 0.5 | 有效点的相对高度窗口，用来滤掉地板与天花板。⚠ **相对车高 > 0.5 m 的点直接进不了代价地图**——高处的悬挂物、高台边缘、对方车体上部都属于"看不见"。调大 → 视野更全，但天花板/灯架可能变成幽灵障碍 |
| `disRatioZ` | 0.2 | 0.2 | 随距离放宽高度窗口的比例。调大 → 远处更宽容（漏检风险）；调小 → 远处更容易成障碍 |
| `decayTime` | 0.5 | 0.2 | 点云时间衰减。调大 → 已消失的障碍在地图上留存更久（保守、易堵路）；调小 → 清除快，但瞬时噪声只生效一帧（**更容易漏检**） |
| `scanVoxelSize` | 0.05 | 0.1 | 地形点云体素下采样。调大 → 省 CPU，但薄杆/细腿可能被抽掉；调小 → 更精确、更费 CPU |
| `useSorting` / `quantileZ` | True / 0.2 | 同 | 地面估计方式与分位数。分位数调大 → 地面基准抬高，**低矮障碍更容易被当平地**；调小 → 更敏感，但坡面/不平地面更容易被误判成障碍（文件注释提醒不要与 `considerDrop` 同开） |
| `considerDrop` | False | — | 凹坑是否算障碍（取相对高度绝对值） |
| `limitGroundLift` / `maxGroundLift` | False / 0.3 | — | 限制地面抬升幅度；坡道场景打开更稳，平坦场地影响不大 |
| `clearDyObs` + `minDyObs*` | True / `minDyObsDis 0.3`、`minDyObsPointNum 1` | — | 动态物体处理。配置文件里对它的注释是"**开启后，有动态物体走过的地方就走不了了**"——动态遮挡会在地图上留下痕迹。调参前务必先确认现场表现（对手车穿过路口后己方是否绕行） |
| `minBlockPointNum` | 10 | — | 判定一个地形块所需的最少点数。**调大 → 抗噪但小障碍（细杆、桩）漏检；调小 → 灵敏但噪声会变成障碍**。这是"误检 vs 漏检"最直接的一个旋钮 |
| `noDataObstacle` / `noDataBlockSkipNum` | False / 0 | — | 无数据区域是否当障碍。`False` 表示"看不见就等于能走"，**与代价地图的 `track_unknown_space: true`（未知不可通行）语义相反**，排查"该停不停"时优先看这里 |
| `voxelPointUpdateThre` / `voxelTimeUpdateThre` | 100 / 1.0 | 100 / 2.0 | 体素更新门槛（点数/时间）。调大 → 更迟更新（更迟钝）；调小 → 更新更勤（CPU 更高、更抖） |
| `clearingDis` | 0.0 | **20.0** | 执行点云清理的距离阈值（外扩用 20 m 的历史点构建全局图） |
| `localTerrainMapRadius` | — | 4.0 | 远程地形图向局部裁剪的半径，影响外扩层在局部地图里的有效范围 |
| `checkTerrainConn` / `terrainConnThre` / `ceilingFilteringThre` | — | False / 0.5 / 2.0 | 地形连通性检查与天花板过滤。打开 `checkTerrainConn` 能滤掉悬空点，但窄通道可能被判不连通（**现场表现常常是"路忽然没了"**） |
| `terrainUnderVehicle` | — | -0.75 | 车下无数据时采用的地面高度 |
| `lowerBoundZ` / `upperBoundZ` | — | -1.5 / 0.5 | 外扩层的有效相对高度窗口 |

⚠ **帧语义不一致（参数文件注释里已标注）**：`terrain_analysis` 源码里 `frame_id` 硬编码为 `odom`，
而代价地图的 `observation_sources.*.sensor_frame` 填的是雷达系（实车 `livox_imu` / 仿真 `front_mid360`）。
排查"障碍整体偏移/抖动"时，第一件事就是在 RViz 里把原始点云与代价地图叠起来看是否错位。

## 3. 代价地图层（最核心的一层）

四份参数文件的 `local_costmap` / `global_costmap` 段。

### 3.1 几何与尺寸

| 参数 | 当前值（实车 Omni / 实车 MINCO / 仿真 Omni / 仿真 MINCO） | 调大 | 调小 |
|---|---|---|---|
| `robot_radius` | 0.33 / **0.33** / 0.33 / **0.40** | 规划更早绕开障碍、更安全；但窄道可能直接"找不到路径" | 贴墙走线更短，但真实碰撞风险上升。⚠ **MINCO 下必须 ≥ `safety.robot_radius + clearance_margin` = 0.38**，否则全局规划会给出"贴着障碍 0.33~0.38 m"的路径，而控制器一条候选轨迹都不敢走（见 §11） |
| `resolution` | 0.05 | 调粗（0.1）→ **地图上不足 1 像素的细障碍会被丢掉**（仓库里有实例：某处真障碍只占 3 个像素） | 调细 → 更精确、CPU 与内存上升 |
| `width` / `height` | 5×5 / 5×5 / 5×5 / **8×8** | 局部地图更大 → 控制器能看到更长的路径（Omni 的有效范围＝半宽 2.5 m），也支持更大的 `approach_velocity_scaling_dist` | 太小 → 局部路径被截得很短，高速时"看到障碍时已经来不及" |
| `rolling_window` | true | — | 只能为 true，否则局部地图不跟随机器人 |

### 3.2 图层与合成

| 参数 | 当前值 | 说明 / 调参后果 |
|---|---|---|
| `plugins` | `["static_layer", "intensity_voxel_layer", "inflation_layer"]` | 顺序即合成顺序。去掉 `static_layer` → 只信实时点云（先验地图里的固定墙不再参与，动态性更强也更险） |
| `combination_method` | 1 | Nav2 约定：0=Overwrite、1=Maximum。`Maximum` 意味着**实时层不会把静态层的障碍"擦掉"** |
| `footprint_clearing_enabled` | **true** | 每个更新周期把车身 footprint 内的代价清成 `FREE_SPACE`。这是防"自己身体成障碍"的必要手段，但副作用是：**任何进入车身 0.33 m 以内的障碍都会被清除**——贴着墙蹭、被对手车贴住时，地图上看不见它。排查"贴住了还往前冲"要想到这里 |
| `update_frequency` / `publish_frequency` | 局部 10 / 5 Hz；全局 5 / 2 Hz | 降低 → 障碍更新滞后（高速时更危险）；提高 → CPU 上升 |
| `track_unknown_space` | 全局 true（主代价地图 + 体素层都是 true）；局部体素层 true | 未知区域按 `NO_INFORMATION` 处理。与 §2 的 `noDataObstacle: False`、与 Theta* 是否 `allow_unknown` 三处语义要一起看，否则会出现"感知说能走、规划说不许走"或反之 |

### 3.3 体素障碍层（`srm27_nav_costmap::IntensityVoxelLayer`）

| 参数 | 当前值 | 调大 | 调小 |
|---|---|---|---|
| `mark_threshold` | **0** | 需要更多体素命中才标记障碍 → 抗噪但小/稀疏障碍漏检 | 已经是最灵敏（1 个点即标记）。**尘埃、反光、地面杂点都可能直接变成致命障碍** |
| `unknown_threshold` | 5 | 更迟把"未知"变成"已知" → 更保守 | 更快认为已知 → 更激进 |
| `z_voxels` / `z_resolution` / `origin_z` | 16 / 0.05 / 0.0 | 决定垂直覆盖范围（当前约 0~0.8 m）。**调大 `z_voxels` 才能看到更高的障碍** | 覆盖变小 → 高障碍从体素层消失 |
| `min_obstacle_height` / `max_obstacle_height` | 0.0 / 2.0 | 上限决定"多高的点还算障碍" | — |
| `min_obstacle_intensity` / `max_obstacle_intensity` | 0.1 / 2.0 | **强度门限**：反射率低的物体（黑色、吸光材质、部分对手车装甲）强度 < 0.1 会被丢弃 → **系统性漏检**。上限亦然（高反光镜面） | 放宽下限能提高检出率，但噪声也一起进来 |

> 该图层**每个周期重建**（`updateBounds` 里 `resetMaps()` 后按最新观测重建），
> 所以障碍的"记忆"完全依赖 `terrain_analysis` 的 `decayTime`。

### 3.4 膨胀层

| 参数 | 当前值 | 调大 | 调小 |
|---|---|---|---|
| `inflation_radius` | 0.5（上游版本是 0.7） | 全局路径离墙更远（更长）、更保守 | 更贴墙、路径更短；**0.5 是从 0.7 特意调小的，为了钻窄道** |
| `cost_scaling_factor` | 4.0 | 代价衰减更慢 → 高代价区更宽，Theta* 更愿意绕远 | 代价衰减更快 → 只有 253 附近才"贵"，路径更贴障碍 |

**再强调一次**：这两个参数只影响 Theta* 的路径形状和 `BackUpFreeSpace` 的方向选择
（它按 `cost ≥ 253` 判定方向是否安全），**不会让 Omni 或 MINCO 减速**。

**硬阻挡边界到底由谁决定（容易搞混，值得记牢）**：

- Theta* 的通行判据是 `26 + 0.9 × cost < 252`，而膨胀层在**内切半径以内**给出 `253`、
  在 `inscribed_radius ~ inflation_radius` 这段环形区给出 `252 × exp(-cost_scaling_factor × (d - inscribed_radius))`。
  于是**真正把格子判成"不可通行"的是内切半径（圆形 footprint 时≈ `robot_radius`）**；
- `inflation_radius` 改变的是那段环形区的**代价高低**（0.33~0.5 m 之间从 252 衰减到约 128），
  从而影响"愿不愿意钻窄道"（路径偏好），而不是"能不能钻"。
  把它调小主要是让窄道变便宜、少绕远；把 `robot_radius` 调小才是真的让车能挤进更窄的口子。

## 4. 全局规划层（Theta*）

参数位置：`planner_server.GridBased`。

| 参数 | 当前值 | 调大 | 调小 |
|---|---|---|---|
| `w_traversal_cost` | 10.0 | 更强烈地绕开高代价区（路径更长、更居中） | 更贴障碍走直线（更短、更险） |
| `w_euc_cost` | 1.0 | 更偏好短路径 | 相对地放大通行费 |
| `w_heuristic_cost` | 1.0 | 调大 → 搜索更快但路径更次优；调小 → 更优但更慢 | — |
| `how_many_corners` | 8 | 8 邻域更优但更慢 | 4 邻域更慢收敛且路径更"方" |
| `allow_unknown` | **未在参数文件里显式设置** | — | — |

> ⚠ `allow_unknown` 是这套栈里最隐蔽的一个避障开关：它决定 Theta* 是否允许穿过 `NO_INFORMATION` 区域。
> 当前配置没写，行为取决于插件默认值。**建议先在参数文件里显式写死再谈调参**，
> 否则"未知区域能不能走"这件事是不可复现的。
>
> 另一个已知边界：Theta* 内部把 `LETHAL_COST` 定义为 **252**，判据是 `cost < 252` 才可通行
> ⇒ `INSCRIBED_INFLATED_OBSTACLE(253)` 已经算不可通行，等效于"规划器保证 `robot_radius` 的余量"。

## 5. 局部控制层

### 5.1 Omni PID 控制器（`srm27_omni_pid_controller`）

避障相关代码只有一处：`computeVelocityCommands()` 里把局部路径**采样成 10 个点**
（`sample_points = 10`），逐点查代价：

```cpp
if (costmap->getCost(mx, my) >= nav2_costmap_2d::INSCRIBED_INFLATED_OBSTACLE) {  // >= 253
  return true;                       // → 抛 PlannerException，本周期不输出速度
}
...
else { return false; }               // 点不在代价地图内 → 直接放行（连告警都被注释掉了）
```

由此产生三个必须知道的特性：

1. **采样点之间有盲区**：2.5 m 的局部路径只查 10 个点，约 0.25 m 一个。
   细杆、桌腿、刚出现的动态障碍若正好落在两点之间，**不会被发现**。
   代价地图 `resolution` 再细也救不了这个——它是在控制器侧丢的空间分辨率。
2. **不做基于代价的减速**：只有"走"和"不走"两种结果，靠近障碍时不会自动放慢。
   想让车在障碍附近变慢，只能靠曲率降速（见速度指南 §4.3）或换 MINCO。
3. **路径出界即放行**：局部路径若有采样点落在代价地图外，函数返回"无碰撞"。
   局部地图只有 5 m 见方（半宽 2.5 m）时，这个分支并不罕见。

失败后的行为由行为树决定（见 §6），控制器本身不做绕障重试。

### 5.2 MINCO-MPC 控制器（`srm27_minco_controller`）

避障在这一层是"连续净空 + 硬校验"，可调项最多：

| 参数 | 当前值 | 调大 | 调小 |
|---|---|---|---|
| `safety.robot_radius` | 0.33 | 更保守，窄通道可能规划失败 | 更贴障碍、真实碰撞风险上升。**必须与代价地图 `robot_radius` 一起改** |
| `safety.clearance_margin` | 0.05 | 硬判据净空 = 0.33+0.05=0.38 抬高，更安全 | 降到 0 就等于"擦着走" |
| `minco.optimization_clearance_margin` | 0.05 | 优化软目标 = 0.43 m 更高，解离障碍更远、更不容易被校验器拒 | 调到 0 → 最优解常常落在硬阈值下方几毫米 → **轨迹被整条丢弃、车来回跑**（仓库实测：0.3737~0.3798 对 required 0.38，40 次拒绝） |
| `minco.w_obstacle` | 100.0（代价单位＝权重×米） | 更怕障碍，绕得更开 | 太小 → 优化解钻进净空阈值 → 校验全部失败；太大 → 压制时间项，表现为"绕大圈、走得慢" |
| `safety.unknown_is_obstacle` | True | — | 设 False 允许穿未知区域（与 `track_unknown_space` 的语义要一致；注意 ESDF 仍把未知当种子） |
| `planning_horizon` | 仿真 3.0 / 实车 2.0 | 提前看到障碍，能提前绕；计算量上升 | 视野不够 → 只能"到跟前才急刹/才失败"。**必须覆盖制动距离**：1.5 m/s、latency 0.1、a=3.0、包络 0.33 ⇒ ≈0.86 m |
| `minco.resample_step` | 0.10 | 前端更粗（快、糙） | 更细（慢、贴线） |
| `map_timeout` | 0.30 s | 容忍更旧的地图（感知慢时更容易通过） | 地图稍旧就拒绝 → 输出零速（点云掉帧时现场表现是"车忽然不动"） |
| `trajectory_max_age` | 0.30 s | 同上 | 同上 |
| `replan_frequency` | 10.0 Hz | 障碍变化响应更快（CPU 上升） | 更迟钝 |
| `safety.braking_deceleration` | 0（= 退化为 `max_linear_accel` 3.0） | 缩短所需制动前缀，校验更容易通过 | 取小 → 短轨迹一律被拒（文档：1.5 m/s 档要求 5.1 s 必然失败） |
| `safety.reaction_latency` | 0.10 s | 短终点轨迹被拒（0.25 s 时 0.26 s 的轨迹只允许 v ≤ 0.033 m/s） | 太乐观 → 来不及停 |
| `sample_dt` / `max_sample_spacing`（代码默认 0.02 s / 0.02 m，**未在参数文件暴露**） | 0.02 / 0.02 | — | 这两个值是"防高速跳过薄障碍"的采样密度，是 MINCO 相对 Omni 的核心优势之一 |

MINCO 的失败信息比 Omni 有用得多：诊断里会给出
`最小净空=… 需要=…`、`有效前缀=…s 需要=…s`、`制动需覆盖=…s`，
**直接告诉你卡在哪一条判据上**，是排查避障问题的第一手信息（见 §8）。

## 6. 恢复层（行为树 + 恢复行为）

`behavior_trees/navigate_to_pose_w_replanning_and_recovery.xml`（`navigate_through_poses_*` 同构）：

```text
RecoveryNode(retries=10)
├─ PipelineSequence
│  ├─ RateController(3 Hz) → ComputePathToPose  ──失败─► ClearGlobalCostmap
│  └─ FollowPath(retries=10)                    ──失败─► ClearLocalCostmap
└─ ReactiveFallback
   ├─ GoalUpdated
   └─ RoundRobin
      ├─ ClearLocalCostmap + ClearGlobalCostmap
      └─ BackUp(backup_dist=1.0, backup_speed=0.2)   ← srm27_nav_behaviors/BackUpFreeSpace
```

| 参数 | 位置 | 当前值 | 调大 | 调小 |
|---|---|---|---|---|
| `FollowPath` 重试次数 | 行为树 | 10 | 更黏着于"清地图再试"，可能长时间原地卡住 | 更早进入脱困动作 |
| `RecoveryNode` 总重试 | 行为树 | 10 | 同上 | 更早放弃任务 |
| `RateController hz` | 行为树 | 3.0 | 重规划更勤（CPU 上升、路径抖动更频繁） | 更迟钝 |
| `backup_speed` | 行为树 | 0.2 | ⚠ 该动作**绕过 velocity_smoother 的限速**。历史上取 1.0 曾造成"窄角落连续高速前冲 71 s" | — |
| `backup_dist` | 行为树 | 1.0 | 单次脱困走得更远 | 太短可能出不了死角 |
| `max_radius` | `behavior_server` | 2.0 | 搜索自由空间的范围更大，方向选择更好 | 太小 → 只能在近处挑方向 |
| `behavior_server.max_rotational_vel` / `min_rotational_vel` / `rotational_acc_lim` | 参数文件 | 1.0 / 0.4 / 3.2 | 自转恢复更快 | 更慢更稳 |
| `simulate_ahead_time` | 参数文件 | 2.0 | 恢复行为看得更远 | 更短视 |

`BackUpFreeSpace` 的实现要点（`src/srm27_nav_plugins/src/behaviors/back_up_free_space.cpp`）：
它**不是倒车**，而是把 ±π 按 π/32 分成 64 个方向、逐方向查代价地图（`cost ≥ 253` 视为阻挡），
取最大安全角区间中点，再输出 `(cos θ, sin θ) × speed` 的全向平移。
所以它的行为对 `robot_radius`（决定 253 的范围）敏感，对 `inflation_radius` 不敏感。

## 7. 定位层（避障的隐含前提）

代价地图里的障碍是**在 odom/map 系里**的，定位一偏，避障全部失效。

| 项 | 当前值 | 说明 |
|---|---|---|
| 定位方式（实车 `script/start_real_nav.sh`） | 四种模式：SLAM 建图 / `--reloc`（small_gicp + 先验 PCD 发布 map→odom）/ `--lio`（Point-LIO 里程计 + **静态** map→odom，脚本标注为"实车推荐"）/ 静态地图无里程计 | `--lio` 模式下 map→odom 是静态的，**里程计漂移不会被纠正**——跑久了障碍会整体错位 |
| `small_gicp_relocalization` | 实车：`num_neighbors 20`、`global_leaf_size 0.1`、`registered_leaf_size 0.05`、`max_dist_sq 3.0`；仿真：`10 / 0.3 / 0.2 / 1.5` | `min_inlier_ratio` / `max_registration_rmse` / `max_translation_step` 用于拦下跳变式配准结果；**调松会让错误的配准被接受，表现为"障碍忽然整体跳一下"** |
| `sensor_scan_generation` | `max_sample_gap` 0.20（实车）/ 0.40（仿真）；`max_position_jump` 0.75；`max_yaw_jump` 1.20 | 超限就不产生差分速度，避免速度尖峰；代价是短时"没有速度反馈" |
| 实车 `/odometry` 频率 | **约 10 Hz**（由雷达帧率决定，`livox_ros_driver2.publish_freq` 与 `point_lio.mapping.lidar_time_inte` 都指向 10 Hz） | 这是 MINCO `state_timeout` 必须 ≥ 0.25 的原因；也是高速时"看到障碍时已经晚了"的根因之一 |
| `point_lio.mapping.ivox_grid_resolution` / `filter_size_surf` / `filter_size_map` | 0.5 / 0.2 / 0.2 | 点云稀疏度；调粗 → CPU 低、细节少（细障碍漏检风险↑） |

```bash
NS=<ns>     # 默认 red_standard_robot1

# --- 代价地图：先看"地图里到底有什么"（建议在 RViz 打开 costmap_raw 看颜色）---

ros2 topic hz /$NS/local_costmap/costmap                    # 应≈publish_frequency

ros2 topic echo /$NS/curvature_points_marker_array --once   # Omni 的曲率计算点

# --- 控制器状态 ---
ros2 topic echo /$NS/cmd_vel_controller --once
ros2 topic echo /$NS/diagnostics                            # 含 MINCO 的净空/前缀/制动诊断
ros2 topic echo /$NS/cmd_vel_nav --once

ros2 run srm27_nav_bringup srm_velocity_monitor.py --ros-args -r __ns:=$NS -p duration:=60 -p output:=/tmp/run.csv

# --- 规划器/控制器行为 ---
ros2 topic echo /$NS/plan --once                            # 全局路径（看是否绕大圈/抄近道）
```

RViz 建议固定三个可视化：`local_costmap/costmap_raw`、`local_plan`、`terrain_map`（原始地形点云）。
**避障问题的定位顺序永远是：原始点云 → 代价地图 → 全局路径 → 局部路径 → 速度。**

**MINCO 的诊断字段是排查避障的第一手材料**（`planning_worker.cpp` 里拼装）：

| 字段 | 含义 | 对应的调参方向 |
|---|---|---|
| `最小净空=…m 需要=0.38m` | 若最小净空恒在 0.37~0.38 徘徊 | 抬高 `optimization_clearance_margin`（软目标比硬判据高一点），或把代价地图 `robot_radius` 抬到 ≥ 0.38 |
| `有效前缀=…s 需要=0.6s` | 前缀覆盖不足 | 加大 `planning_horizon`、复核 `braking_deceleration` / `reaction_latency` |
| `制动需覆盖=…s` | 需要的停车时间 | `braking_deceleration` 取实测值；或降速 |
| `terminal=…` | 视野截断 / 全局目标 / 障碍边界 | 边界停稳属正常；频繁出现说明视野或地图太小 |
| `reason`（第一处失败原因） | 直接告诉你哪条判据失败 | 按上表对症 |

## 9. 标准避障调试流程

1. **复现场景**：不要用整场比赛试参数。用 `missions/` 里的单段航点脚本 + 固定障碍摆位，
   或在仿真里用 `227_1006` 这类已知有窄点的地图（仓库记录过 #2→#3 最紧处净空只有 0.36 m）。
2. **确认现象层次**（这一步决定后面所有动作）：
   - 原始点云里有没有那个障碍？→ 没有 → §2 感知层（`maxRelZ`/`minBlockPointNum`/强度门限）
   - 代价地图里有没有？→ 没有 → §3 代价地图层（`resolution`、`mark_threshold`、`footprint_clearing`、`sensor_frame` 帧语义）
   - 全局路径绕没绕？→ 没绕 → §4 规划层（`allow_unknown`、`w_traversal_cost`、`inflation_radius`）
   - 路径绕了但车不跟 / 车停住 → §5 控制层（Omni 的 10 点采样与出界放行，或 MINCO 的净空/前缀判据）
   - 车反复抖动、被 recovery 拖来拖去 → §6 恢复层 + 进度检查器
3. **一次只改一个参数，改完立刻重跑同一段**。
   代价地图类参数改完**必须重启**（`inflation_radius`、`robot_radius`、`plugins` 等），
   控制器/规划器的多数参数支持 `ros2 param set`（Omni 的动态参数清单见速度指南 §9）。
4. **区分"误检"与"漏检"**，它们的方向相反。任何一次调参都要同时问：
   这个改动会不会让某类障碍更容易被漏掉？（`mark_threshold`、`minBlockPointNum`、
   `intensity` 门限、`resolution`、`maxRelZ`、`min_obstacle_height` 全都在这条线上。）
5. **回归**：固定场景跑 3 遍，比较"是否碰撞 / 最小净空 / recovery 次数 / 任务耗时"。
   净空变好但 recovery 变多，说明参数方向对、幅度过大（尤其 `robot_radius` 与 `inflation_radius`）。

## 10. 症状 → 处方

| 症状 | 可能原因 | 先查 | 处理 |
|---|---|---|---|
| 蹭墙、贴障碍擦过 | 规划只保证 `robot_radius`；Omni 阈值是 253，允许路径中心走到 0.33 m | 局部路径与 `costmap_raw` 叠加 | 抬 `robot_radius`（MINCO 必须 ≥0.38）、抬 `inflation_radius`、或抬 `w_traversal_cost` |
| 细杆/桌腿直接穿过去 | ①控制器 10 点采样漏检 ②`resolution` 太粗导致障碍不足 1 像素 ③强度门限把它滤掉 ④`minBlockPointNum` 太大 | 原始点云 vs 代价地图 | 按 ①②③④ 顺序排查；根本解法是换 MINCO（有 0.02 m 采样间距的硬校验） |
| 车在宽通道里也绕大圈 | `inflation_radius`/`cost_scaling_factor` 太大，或 `w_traversal_cost` 太大，或 `minco.w_obstacle` 太大 | 全局路径 | 下调对应项；注意别把窄道能力一起削掉 |
| 窄道进不去，报"找不到路径" | `robot_radius`（内切半径）≥ 通道半宽 —— 这才是硬约束；`inflation_radius` 只让它变"贵" | 全局代价地图 + 地图分辨率 | 先量最小通道宽度；必要时小幅下调 `robot_radius`（**但要同步 `safety.robot_radius`/`clearance_margin`，别把 MINCO 的净空判据搞崩**），`inflation_radius` 只用来减少无谓绕远 |
| 车到障碍前**不减速**，直接抛"Collision detected" | Omni 本来就没有 proximity 减速；障碍是在局部路径采样点上被发现的 | 控制器日志 | 用曲率降速近似（速度指南 §4.3），或换 MINCO |
| 车忽然停住不动，10 s 后 `Failed to make progress` | MINCO：候选轨迹被校验器全部拒绝（净空/前缀/制动/地图超时）；Omni：碰撞检查持续失败 | `/<ns>/diagnostics` 的 reason | 按 §8 的诊断字段对症；常见根因是**代价地图 `robot_radius` < 控制器要求净空** |
| 反复 recovery、原地来回跑 | 控制器持续失败 + 恢复动作把车推回同一位置 | 行为树日志 + 地图 | 修根因（净空/局部地图尺寸）；临时可增大 `planning_horizon`、缩小重试次数 |
| 车贴着障碍时"看不见它了" | `footprint_clearing_enabled: true` 把 footprint 内代价清成自由 | 代价地图（障碍进入 0.33 m 内就消失） | 不能关（关了车身会变成障碍）；改成在速度/净空层面留够余量 |
| 障碍在地图上整体偏移/抖动 | 帧语义（`terrain_map` 实际是 odom 系而 `sensor_frame` 填雷达系）、TF 延迟、定位跳变 | RViz 叠原始点云与代价地图 | 核对 `sensor_frame`、`transform_tolerance`、定位模式与 `small_gicp` 的拦跳变阈值 |
| 已消失的障碍还挡着路 | `decayTime` 太长、`voxelTimeUpdateThre` 太大（体素更新迟钝）；或静态地图里本来就有这个障碍 | 代价地图随时间的演化 + 原始点云 | 下调 `decayTime` / `voxelTimeUpdateThre`；若障碍来自 `static_layer`（先验地图），只能改地图 |
| 对手车穿过路口后己方忽然绕行 | 动态障碍残留 / `clearDyObs` 的副作用 | 原始点云时间序列 | 见 §2 的 `clearDyObs` 说明，需要按现场表现单独确认 |
| 高处障碍（悬挂物、高台边缘）看不见 | `maxRelZ: 0.5`（相对车高）把高点滤掉了；体素层垂直覆盖只有约 0.8 m | 原始点云 | 抬 `maxRelZ`、抬 `z_voxels`；注意天花板/灯架会变成幽灵障碍 |
| 该走的时候不走（未知区域） | 三处 unknown 语义不一致：costmap `track_unknown_space: true`、感知 `noDataObstacle: False`、Theta* `allow_unknown` 未显式设置 | 三个参数一起看 | 显式统一语义，别让默认值决定行为 |

## 12. 一页速查

**先问自己三个问题：**

1. **用的是哪个控制器？** Omni → 避障是二值的，重点在代价地图 + 全局规划；MINCO → 重点是净空与校验判据。
2. **现象是"误检"还是"漏检"？** 误检（不该挡的挡了）改 `mark_threshold`↑/`minBlockPointNum`↑/
   `decayTime`↓/`min_obstacle_intensity` 收紧；
   漏检（该挡的没挡）改 `mark_threshold`↓/`minBlockPointNum`↓/`min_obstacle_intensity` 放宽/`resolution`↓/`maxRelZ`↑/`z_voxels`↑。
3. **失败是在"看不见"还是在"不敢走"？** 看不见 → §2/§3；不敢走（路径贴障碍、校验拒绝）→ §4/§5。

**改动的安全边界：**

- 代价地图 `robot_radius` **≥ 0.38**（MINCO）；同一次改动要同步 local 与 global 两份。
- `xy_goal_tolerance` **> 行为树航点跳过半径**（0.35 / route-aware 那份 0.60）。
- "能不能钻过某条窄道"由 `robot_radius`（内切半径）决定，不由 `inflation_radius` 决定；
  `inflation_radius` 只决定"值不值得钻"（代价高低 → 是否绕远）。要钻更窄的口子就调 `robot_radius`，
  但要同时接受真实碰撞风险。
- 任何"放宽净空/抬高门限"的改动都要在已知窄点地图上回归一次（`227_1006` 是最紧的那张）。
