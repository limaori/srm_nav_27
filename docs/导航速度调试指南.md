# 导航速度调试指南

> 适用对象：`srm27_nav_27` 的 Nav2 导航速度链路（Omni PID 控制器 / MINCO-MPC 控制器）。
> 本文只讲**车跑多快**；障碍物怎么躲、净空怎么调见 [`导航避障调试指南.md`](./导航避障调试指南.md)。
> 文中数值为当前参数文件里的实际值，改参数前请以文件为准（**部分注释已过期**，清单见避障指南 §11）。

---

## 0. 一句话结论

**实际导航速度 = 链路上所有限幅层的最小值。**

只改一处通常看不到任何效果；提速必须"三处同步"，而且在动参数之前必须先算清两件事：
**制动距离**（`v·latency + v²/(2a) + 车身包络`）和**切内弯的横向偏移量**（必须小于行为树的航点跳过半径）。

## 1. 先确认你改的是哪份文件、哪条链

| 入口 | 脚本 | 默认参数文件 | 控制器 |
|---|---|---|---|
| 仿真 | `script/start_sim_nav.sh` | `src/srm27_navigation/srm27_nav_bringup/config/simulation/nav2_params_srm.yaml` | Omni |
| 仿真（MINCO） | `PARAMS_FILE=.../simulation/nav2_params_srm_minco.yaml bash script/start_sim_nav.sh` | `.../simulation/nav2_params_srm_minco.yaml` | MINCO |
| 实车 | `script/start_real_nav.sh` | `src/srm27_navigation/srm27_nav_bringup/config/real/nav2_params_srm.yaml` | Omni |
| 实车（MINCO） | `script/start_real_nav.sh --controller minco` | `.../real/nav2_params_srm_minco.yaml` | MINCO |

> ⚠ `src/srm27_bringup/params/node_params.yaml` 是上游 pb2025 那份（`max_velocity [2.5,2.5,3.0]`），
> **不是当前入口加载的文件**，改它没有任何效果。

速度链（`start_sim_nav.sh` / `start_real_nav.sh` 的头部注释也有同一份说明）：

```text
【仿真】controller_server ─cmd_vel_controller─► velocity_smoother ─cmd_vel_nav─┐
                                                                  srm_cmd_mux ─┴─► cmd_vel_sim ─► 速度适配器 ─► Gazebo

【实车】controller_server ─cmd_vel_controller─► velocity_smoother ─cmd_vel_nav2_result─┐
                                       fake_vel_transform ─► cmd_vel_chassis ─► srm27_nav_protocol ─► 串口
```

实车**不经过 `srm_cmd_mux`**，仿真**不经过串口协议**——这是两侧限速必须分别核对的原因。

| 层 | 参数 | 仿真 | 实车 | 文件 |
|---|---|---|---|---|
| 控制器（Omni） | `FollowPath.v_linear_max` / `v_linear_min` | 1.5 / -1.5 | 1.5 / -1.5 | 两份 `nav2_params_srm.yaml` |
| 控制器（Omni） | `FollowPath.v_angular_max` / `v_angular_min` | 1.0 / -1.0 | 1.0 / -1.0 | 同上（导航 ω 实际被下游钳 0） |
| 控制器（MINCO） | `FollowPath.limits.max_linear_speed` / `max_linear_accel` | 1.50 / 3.00 | 1.50 / 3.00 | 两份 `*_minco.yaml` |
| 平滑器 | `velocity_smoother.max_velocity` / `min_velocity` | `[1.5, 1.5, 0.0]` / `[-1.5, -1.5, 0.0]` | 同左 | 四份参数文件 |
| 平滑器 | `max_accel` / `max_decel` | `[3.0, 3.0, 0.0]` / `[-3.0, -3.0, 0.0]` | 同左 | 同上 |
| 合成（仅仿真） | `srm_cmd_mux.vx_max` / `vy_max` / **`v_max`** | 1.5 / 1.5 / **1.5** | — | `src/srm27_chassis_control/config/srm_chassis_control.yaml` |
| 串口（仅实车） | `max_vx` / `max_vy` / `max_wz` | — | 2.5 / 2.5 / 1.0 | `src/srm27_nav_protocol/config/srm27_nav_protocol.yaml` |
| 手柄（手动） | `scale_chassis` / `scale_chassis_turbo` | 2.5 / 4.0 | 2.5 / 4.0 | 四份参数文件 |

**有效平移限速两侧都是 1.5 m/s，导航 yaw 两侧都是 0**（自转走 `rotation_controller` 独立链路，不归导航管）。

### 两个反直觉点

1. `velocity_smoother` 是**按分量**钳位（`[1.5, 1.5]`），所以 `vx=vy=1.5` 时合速度可达 **2.12 m/s**。
   仿真里 `srm_cmd_mux.v_max=1.5` 会把模长压回去，实车没有 mux、串口也只按分量限 2.5
   → **斜向高速时仿真比实车更慢**，A/B 对照实验要留意这一点。
2. `srm_cmd_mux` 的 `v_max` 是 `cmd_vel_sim` 前的最后一道模长钳位。
   只把 controller 和 smoother 抬上去、mux 留低，最终速度仍然等于 mux 的值
   （文件注释里专门写了这条警告）。

## 3. 提速前：先定位瓶颈在哪一层

```bash
# 1) 控制器原始输出（smoother 之前）
ros2 topic echo /<ns>/cmd_vel_controller --once
# 2) 导航链路出口（smoother 之后）
ros2 topic echo /<ns>/cmd_vel_nav --once          # 仿真：再进 mux
ros2 topic echo /<ns>/cmd_vel_nav2_result --once  # 实车
# 3) 最终执行命令与实际速度
ros2 topic echo /<ns>/cmd_vel_sim --once          # 仿真
ros2 topic hz   /<ns>/cmd_vel_sim                 # 应约 200 Hz
# 4) 一次性记录三路速度 + 位姿到 CSV（推荐，比肉眼看 echo 可靠）
ros2 run srm27_nav_bringup srm_velocity_monitor.py --ros-args -r __ns:=/<ns> -p duration:=60 -p output:=/tmp/run.csv
```

判读方法：

| 现象 | 结论 |
|---|---|
| `cmd_vel_controller` 就不到 1.5 | 控制器层是瓶颈：看 §4.1 / §4.5（PID 与前瞻） |
| 控制器有 1.5、`cmd_vel_nav` 没有 | smoother 是瓶颈：`max_velocity` 或 `max_accel` 太小 |
| `cmd_vel_nav` 有、`cmd_vel_sim` 没有 | mux 的 `v_max` 是瓶颈（仿真） |
| 三处都有 1.5，但 odom 实测只有 1.1 | **执行端**问题：底盘/仿真插件跟不上，或加速度不足没跑满（见 §4.2），不是限速问题 |
| 直道够快、弯道慢得离谱 | 曲率降速（§4.3）或 MINCO 的 `corner_speed_ratio` |

## 4. 参数分组详解（改大 / 改小的后果）

### 4.1 硬上限类

| 参数 | 调大 | 调小 |
|---|---|---|
| `FollowPath.v_linear_max`（Omni） | 直道与弯道的顶速一起抬高。它是 Omni PID 的输出饱和值，**最直接的"油门"** | 全链路变慢；过低会被进度检查器判"没动"（§5） |
| `velocity_smoother.max_velocity` / `min_velocity` | 必须 ≥ 控制器上限才有意义 | **把它调小于控制器上限，会把前面所有提速全部吃掉**（最常见的"改了没效果"） |
| `velocity_smoother.max_accel` / `max_decel` | 更快到顶速、起停更冲；打滑与里程计漂移风险上升 | 平顺但迟钝；**短距离航段根本达不到 `max_velocity`** |
| `srm_cmd_mux.vx_max` / `vy_max` / `v_max`（仿真） | 抬高仿真执行上限 | 留低＝静默削速度；`v_max` 尤其致命 |
| `max_vx` / `max_vy` / `max_wz`（实车串口） | 当前 2.5 不是瓶颈 | 调小会在串口前削速度，且诊断上不显眼 |
| `FollowPath.limits.max_linear_speed`（MINCO） | 抬高 MINCO 轨迹的速度硬上限；不同步抬 `w_jerk/w_time` 会用不满 | 低于 smoother 时把速度全吃掉（文档记录过的 P1 问题） |
| `scale_chassis` / `scale_chassis_turbo` | 仅手柄。实车手柄直接进 `cmd_vel_chassis`，**绕过 smoother**，所以这里能超过导航限速 | 仅影响手动手感 |

### 4.2 加速度与平滑类

- 只抬 `max_velocity` 不抬 `max_accel`：2 m 以内的航段基本跑不满（`0→1.5 m/s` 需 0.5 s、约 0.375 m）。
- `max_decel` 决定能否在容差内停住；调小会让停车点越过目标。
- MINCO 侧对应 `limits.max_linear_accel` 与 `safety.braking_deceleration`（当前 0，含义是"退化为使用 `max_linear_accel`"）。

### 4.3 弯道降速类（Omni 专属）

| 参数 | 当前值 | 调大 | 调小 |
|---|---|---|---|
| `curvature_min` | 0.4 | 更缓的弯就开始降速 → 全程更慢、更安全 | 弯里保速，切内弯偏移加大、吃掉 0.33 m 余量 |
| `curvature_max` | 0.7 | 降速区间变宽，只有急弯才用最大降速比 | 更容易触发最大降速 |
| `reduction_ratio_at_high_curvature` | 0.5 | →1.0 几乎不降速（快、险） | →0.2 急弯几乎停车 |
| `curvature_forward_dist` / `backward_dist` | 0.7 / 0.3 | 曲率估计更提前/更平滑，降速更早 | 反应更灵敏但更抖 |
| `max_velocity_scaling_factor_rate` | 0.9 | 缩放因子变化更快，入弯降速与出弯恢复更猛 | 更平滑但入弯偏晚 |
| `min_approach_linear_velocity` | 0.4 | **双重影响**：终点减速地板，同时是弯道降速地板（代码里 `max(scaled, 2×0.4)=0.8`）→ 弯道不低于 0.8 m/s，快但更擦障碍 | 终点更慢更稳；弯道允许降得更低 |
| `approach_velocity_scaling_dist` | 1.0 | 提前减速，终点更平顺、总时间更长 | 更晚减速、冲进容差；**必须小于局部代价地图半宽（2.5 m）**，代码里有告警检查 |

### 4.4 终点与到点判定类

| 参数 | 当前值 | 影响 |
|---|---|---|
| `general_goal_checker.xy_goal_tolerance` | Omni 0.4；MINCO 仿真/实车均 0.50 | 调大 → 提前 0.4~0.5 m 就算到达，**账面更快**但落点更粗；调小 → 更精确但易振荡。**必须仍大于行为树航点跳过半径（0.35）** |
| `yaw_goal_tolerance` | 6.28（自由） | 调小后才要求朝向，会拖长到点时间 |
| MINCO `terminal_reached_radius` | 0.20 | 调大 → 更早认为"已到路径末端"；调小 → 更容易报 `no_path` |
| MINCO `goal_change_tolerance` | 0.10 | 同一任务内"路径刷新 vs 换目标"的判定阈值 |
| MINCO `terminal.tolerance` | 0（跟随目标检查器容差） | 终点急刹的进入半径；调大 → 更早急刹，进入速度 ∝ √(2·a·tol)（tol 0.40、a=3 时约 1.5 m/s，几乎满速急刹）；调小 → 更晚、更平顺，但可能冲出容差 |
| MINCO `terminal_speed` | 仿真 0.8 / 实车 0.0 | 视野截断段的末端速度；实车 0 表示到目标必须停稳 |

### 4.5 前瞻与 PID（Omni 的"隐性油门"，最容易踩坑）

Omni 输出的速度 = `PID(到前瞻点的距离)`，再被 `[v_linear_min, v_linear_max]` 饱和；
而前瞻距离在 `use_velocity_scaled_lookahead_dist: true` 时是
`clamp(|当前速度| × lookahead_time, min_lookahead_dist, max_lookahead_dist)`
——**`lookahead_dist: 2.0` 这个值根本不参与计算**。

| 参数 | 当前值 | 调大 | 调小 |
|---|---|---|---|
| `lookahead_time` | 0.6 | 前瞻更远 → 误差项更大 → 更容易顶到 `v_linear_max`，起步更快；代价是切内弯偏移更大 | 跟踪更贴线，但可能**永远达不到顶速**；前瞻 0.3 m 时 10 cm 横向误差≈18°，`enable_rotation=false` 下方向误差直接变成横向平移速度 → **"画龙"** |
| `max_lookahead_dist` / `min_lookahead_dist` | 0.6 / 0.3 | 上限抬高＝变相提高可达速度 | 上限压住＝给速度加了软上限 |
| `translation_kp` | 3.0 | 收敛快，可能超调振荡 | **低于约 2.5（=1.5/0.6）时，P 项最大只有 0.6×2.5=1.5，恰好顶不满限速**，等于给速度上了软钳 |
| `translation_ki` / `translation_kd` | 0.1 / 0.3 | ki 大 → 静差小但易摆尾；kd 大 → 遇噪声抖 | ki 小 → 稳态跟不上；kd 小 → 阻尼不足 |
| `min_max_sum_error` | 1.0 | — | **死参数**：插件读它、也能动态设置，但代码里没有任何地方使用 |
| `transform_tolerance` | 0.1 | TF 落后时更容易通过，但位姿更旧 | 太小时频繁抛 TF 异常 |

> ⚠ `control_duration_ = 1/controller_frequency` 直接进 PID 的 D/I 项：
> **改 `controller_frequency` 等于同时改了等效 kd/ki**，必须重新整定增益。

### 4.6 MINCO 专属

| 参数 | 当前值 | 调大 | 调小 |
|---|---|---|---|
| `minco.w_time` | 10.0 | 优化更偏好短时间 → **更快**（MINCO 的"油门"） | 更懒散、更慢 |
| `minco.w_jerk` | 0.2 | 更平顺但**压速度**（文档实测：1.0 时 2 m 起停只跑到 1.116/1.5 m/s，约 74% 限速；0.2 时 1.438 m/s） | 更快但更冲 |
| `minco.w_velocity` / `w_acceleration` | 60 / 300 | 更严格守限速 | 太小 → 最优点越过硬上限 → 校验器把候选轨迹**整条丢弃** → 车不动、反复 recovery |
| `minco.corner_speed_ratio` | 0.35 | 弯道保速（快、险） | 弯道更慢 |
| `minco.resample_step` | 0.10 | 前端弧长重采样更粗，计算更快、跟踪更糙 | 更细、更慢 |
| `mpc.command_lookahead` | 0.20 | 加速更提前、更激进 | **太小 → 车根本不起步**（速度层 MPC 的第 0 拍命令≈0，文档有现场复现） |
| `mpc.prediction_dt × prediction_steps` | 0.02 × 30 = 0.6 s | 直接决定校验器要求的"有效前缀时长"；调大会更容易拒绝短轨迹 | 太短＝只看很短一段，风险上升 |
| `replan_frequency` | 10.0 | 重规划更勤（CPU 上升） | 反应迟钝 |
| `planning_horizon` | 仿真 3.0 / 实车 2.0 | 提前看到弯道与障碍，能保速；计算量上升 | 视野不够 → 急刹、规划失败。**必须覆盖制动距离**：1.5 m/s、latency 0.1、a=3.0、包络 0.33 ⇒ ≈0.86 m |
| `safety.braking_deceleration` | 0 / 0 | 取实测值。调大会缩短所需制动前缀，更容易通过校验 | 取小会把候选轨迹一律判死（文档：1.5 m/s 档要求 5.1 s 必然失败） |
| `safety.reaction_latency` | 仿真实车均 0.10（0 时退化为 `state_timeout`） | 短终点轨迹被拒（实测取 0.25 s 时，0.26 s 的终点轨迹只允许 v ≤ 0.033 m/s） | 太乐观 → 冲过终点 |

### 4.7 频率、延迟、超时

| 参数 | 当前值 | 说明 |
|---|---|---|
| `controller_frequency` | Omni 20 Hz；MINCO 仿真/实车 50 Hz | 提高 → 跟踪更紧、延迟更小；降低 → 跟随滞后、抖动（Omni 还会改变 PID 的 dt） |
| `velocity_smoother.smoothing_frequency` | 20 Hz | 低于控制器频率时，smoother 的输出节拍成为瓶颈 |
| `velocity_smoother.scale_velocities` | False | True 时超限按比例缩放各分量（保持方向）；False 时各分量独立钳位（斜向限速更宽） |
| `srm_cmd_mux.publish_rate` / `nav_timeout` | 200 Hz / 0.3 s | `nav_timeout` 是仿真侧超时清零，调大在异常时更危险 |
| `velocity_smoother.velocity_timeout` | 1.0 s | 命令中断后归零的兜底时间 |
| `srm_sim.yaml velocity.command_timeout` / `protocol.cmd_timeout_sec` | 0.1 s / 0.5 s | 执行端归零时间，不是限速 |
| `behavior_server.max_rotational_vel` / `min_rotational_vel` / `rotational_acc_lim` | 1.0 / 0.4 / 3.2 | 只影响恢复行为耗时 |

## 5. 隐性限速：把"慢"变成"失败"的参数

| 参数 | 当前值 | 影响 |
|---|---|---|
| `progress_checker.required_movement_radius` / `movement_time_allowance` | 0.5 m / 10 s | 位移限速到 <0.05 m/s 时，10 s 内移动不到 0.5 m → `Failed to make progress` → recovery 拖车。**这是低限速档最容易踩的坑** |
| `failure_tolerance` | 0.3 | 调小 → 抖动更早触发恢复行为 |
| `controller_server.min_y_velocity_threshold` | **Omni 两份都是 0.5**；MINCO 两份 0.001 | Nav2 用它把里程计速度做阈值化后再喂给**目标检查器**：<0.5 m/s 的横移分量在判定"停稳"时被当成 0。低速横移调参时它会干扰现象判断（仓库建议改 0.001） |
| `min_x_velocity_threshold` / `min_theta_velocity_threshold` | 0.001 | 同上，量级正常 |
| 行为树 `RateController hz` | 3.0 | 重规划频率；跟踪高动态目标时偏低 |
| 行为树 `BackUp backup_speed` | 0.2 | 脱困动作**绕过 smoother**，提速后要复核它是否仍小于 `v_linear_max` |

## 6. 标准提速流程（逐级提速 checklist）

**每次只提一档（建议 0.25~0.5 m/s 一档），跑通再提下一档。**

1. **算制动距离**（P5 制动辨识前先用现有值估算）：
   `d_stop = v·latency + v²/(2·a) + 车身包络`
   例：1.5 m/s、latency 0.1、a=3.0、包络 0.33 ⇒ ≈0.86 m（< 实车 `planning_horizon` 2.0 m、< 仿真 3.0 m）。
   要到 3.0 m/s ⇒ ≈2.0 m，已无余量 → **必须先加大 `planning_horizon` 与局部代价地图**。
2. **算切弯偏移**：前瞻越大、速度越高，切内弯的横向偏移越大；**偏移必须小于行为树航点跳过半径**
   （`navigate_through_poses_w_replanning_and_recovery.xml` 的 `radius=0.35`，route-aware 那份是 0.60）。
   这是 2026-10-09 "仿真提速档 3.0 被撤销"的直接原因。
3. **三处同步改**（缺一处就等于没改）：

   | # | 位置 | 参数 |
   |---|---|---|
   | 1 | `FollowPath.v_linear_max` / `v_linear_min`（Omni）或 `FollowPath.limits.max_linear_speed`（MINCO） | 控制器上限 |
   | 2 | `velocity_smoother.max_velocity` / `min_velocity`（+ 按比例改 `max_accel`/`max_decel`） | 平滑器上限 |
   | 3 | 仿真：`srm_cmd_mux.vx_max`/`vy_max`/`v_max`；实车：`srm27_nav_protocol.max_vx`/`max_vy` | 末端钳位 |

4. **同步检查联动量**：
   - MINCO：`minco.w_jerk`（提速后要重新标定，否则用不满新限速）、`safety.braking_deceleration`、`planning_horizon`、`mpc.command_lookahead`；
   - Omni：`lookahead_time` / `max_lookahead_dist`（与切弯偏移一起看）、`curvature_*`；
   - 通用：`progress_checker`、`xy_goal_tolerance` 与行为树 radius 的大小关系。
5. **记录与验证**：跑 `srm_velocity_monitor.py`，确认 `cmd_vel_nav`、`cmd_vel_sim`、`odometry.twist` 三路速度曲线；
   检查 `/<ns>/diagnostics`（如 `nav_wz_dropped_count`，非 0 说明导航误发了 ω）。
6. **回归**：同一条航点任务跑三遍，比较"总时长 / 最大速度 / 到达精度 / recovery 次数"。
   只快了一点点但 recovery 次数翻倍，就是档位选错了。

## 7. 症状速查

| 症状 | 最可能的原因 | 处理 |
|---|---|---|
| 改了参数没有任何变化 | 下游某层钳住了（smoother / mux / 串口）；或改的是 `node_params.yaml` | 按 §3 逐层 echo 定位 |
| 直道也只有 1.0 m/s 左右，控制器输出不到 1.5 | Omni：`translation_kp` 偏低或前瞻上限太小（误差项顶不满饱和）；MINCO：`w_jerk` 太大 | §4.5 / §4.6 |
| 直道能到 1.5，2 m 段跑不到 | `max_accel` 偏小 | §4.2 |
| 弯道突然很慢 | Omni 曲率降速；MINCO `corner_speed_ratio` | §4.3 / §4.6 |
| 到点前"急刹"很冲 | MINCO `terminal.tolerance` 偏大（进容差立即零速）；或 `approach_velocity_scaling_dist` 太小 | §4.4 |
| 车在路径两侧"画龙" | 前瞻过小 + `enable_rotation=false` | `lookahead_time`/`min_lookahead_dist` 加大，或回退 0.8/0.4/0.8 |
| 车不动，10 s 后报 `Failed to make progress` | 限速档太低、`progress_checker` 判失败；或 MINCO 候选轨迹被校验器全部拒绝（见避障指南） | §5 / 避障指南 §5 |
| 提速后车在途经点之间来回跑 | 切弯偏移 > 航点跳过半径 | 降速回标定档，或加大行为树 radius 并同步 `xy_goal_tolerance` |
| 手感速度与导航速度不一致 | 手柄走 `cmd_vel_chassis`，**绕过 smoother** | 分开核对 |

## 9. 运行时调参与回滚

Omni 插件的多数参数**支持运行时修改，不必重启**（代码里有 `on_set_parameters` 分支）：

```bash
ros2 param set /controller_server FollowPath.v_linear_max 2.0
ros2 param set /controller_server FollowPath.lookahead_time 0.8
ros2 param set /controller_server FollowPath.curvature_min 0.5
ros2 param set /controller_server FollowPath.max_velocity_scaling_factor_rate 0.7
```

`velocity_smoother` 支持 Nav2 的动态参数。`srm_cmd_mux` 的限幅参数**没有**动态回调
（只有 `rotation_test_sender` 有），改它要改文件并重启。

回滚建议：每次提速前 `git diff` 留档，或在参数文件里把当前值写成注释（现有文件已经在做这件事，
例如实车 `velocity_smoother` 的 `max_velocity [1.5, 1.5, 0.0]` 后面写了"硬上限：首跑限速，跑通后再放"）。
