# 云台转动时世界点云“平移绕圈”定位记录（2026-11-24）

## 现象

底盘静止、只转云台时，RViz 里整片点云/障碍物绕车体来回摆；车定位看起来还行。
backend 模式和 `--lio` 前端模式都能复现，先排除了 backend 的 `map→odom` 修正。

## 结论：不是 yaw，是世界点云的平移绕圈

`debug_tools/capture_gimbal_cloud_rotation.py` 的 yaw 判据显示 5 路点云斜率都在
-0.02~+0.04；但新增的“锚点平移对云台角做谐波拟合”给出一个干净的圆：

| 话题 | backend 包 R / 残差 | `--lio` 包 R / 残差 | 同段 `odom→base` R |
| --- | ---: | ---: | ---: |
| `/livox/lidar/pointcloud` | 8.7 / 0.6 cm | 8.6 / 1.4 cm | 1.8 / 1.9 cm |
| `/registered_scan` | **9.8 / 1.1 cm** | **9.6 / 1.5 cm** | 1.8 / 1.9 cm |
| `/sensor_scan` | 9.8 / 1.1 cm | 9.2 / 1.7 cm | 1.8 / 1.9 cm |
| `/terrain_map` | 8.6 / 1.0 cm | 6.9 / 1.4 cm | 1.8 / 1.9 cm |
| `/terrain_map_ext` | 21.7 / 1.6 cm | 7.6 / 1.1 cm | 1.8 / 1.9 cm |

点云绕 ~9.6 cm，车位姿只绕 ~1.8 cm ⇒ 两者不自洽；障碍物相对车体绕圈。残差 1~2 cm
远小于半径，不是配准噪声。

## 根因

`zlio_bridge` 的 `pose_body_offset_xyz: [0.009, -0.226, -0.130]` 是**车体/雷达系常量平移**，
用来修 ZLIO 在“云台绕偏轴自转”下的位姿圆。`pose_body_offset_apply_to_cloud: true` 时
同一个 offset 也被右乘到世界点云上；云台一转，这个 body 常量在世界系里就是一个圆，
所以障碍物跟着绕。

实测 offset 对**位姿**有效（`odom→base` R≈1.8 cm），但对世界点云留下 R≈9.6 cm；
旧注释“true 时位姿和点云一起改、相对几何仍然是外参 A、避障不受影响”在实车上不成立。

## 改动

- `src/bringup/srm27_nav_bringup/config/real/current/nav2_params_srm_minco_fakeyaw.yaml`
  与 `mapping_params.yaml`：`pose_body_offset_apply_to_cloud: False`（只补位姿；
  世界点云走 ZLIO 原始位姿），两份必须同值；
- `zlio_bridge.py`：默认值与注释同步为 false，启动日志说明当前作用范围；
- `test_zlio_bridge_math.py`：配置断言从“必须 true”改为“必须 false”，并写明实测；
- `debug_tools/capture_gimbal_cloud_rotation.py`：新增“平移绕圈”判据/报告列
  （`--orbit-min` 默认 3 cm）和 `translation_orbit` 判读，不再只看 yaw。

## 验证

- 现场：`false` 后 RViz 里云台自转时的点云绕圈消失；位姿补偿保留。
- 建议复采：3 个来回即可（不用刻意加时长），看工具的“平移绕圈”列；点云 R 应接近 0，
  `odom→base` R 仍在 ~1.8 cm 量级。
- 另一个独立问题：快速转动时 `odom→lidar` TF 与 `/lidar_odometry` 有 2~5° 单帧尖峰
  （raw Livox 用 TF 链显示时会跳；`registered_scan`/`sensor_scan` 不受影响），与本绕圈无关。
