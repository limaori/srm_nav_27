# 2026-11-26 直道贴边 + 拐弯切内道：分层定位与修复

> 症状：直道总是偏在一侧、贴着墙走；90° 弯切内道，弯心偏差 0.5~0.66 m，
> 实际轨迹压着内墙过；换速度档后表现差别很大，靠"再调调参数"始终调不稳。
>
> 结论先说：**这是两层的两个病**——直道贴边在**平滑层**（走廊约束太松），
> 拐弯切内道在 **MINCO 层**（代价函数缺"参考吸引项"）。控制层是干净的。

## 0. 先分层，再改参数

链路（每一层都有自己的话题，录包时一起录）：

```
/plan (YAstar, map) → /plan_smoothed (MinimumSnap + SFC, map)
  → planning_input_path (裁剪 6 m + 净空预推, odom)
  → minco_trajectory (odom) → mpc_prediction (odom) → /odometry
```

判据与基线实测（同目标：直道 + 90° 弯 + 直道，2.6 m/s 档）：

| 对照 | 指标 | 基线 | 读法 |
| --- | --- | --- | --- |
| `/plan` → `/plan_smoothed` | 最大偏移 | **0.555 m** | 平滑在改几何（把稀疏折线的角圆掉） |
| 平滑路径的净空 | 直道中位/偏心 | 0.81 m / **0.48 m** | 平滑后仍偏一侧 → 直道贴边在这一层 |
| 参考 → MINCO | 直道 中位/最大 | 0.013 / 0.385 m | 直道基本贴参考 |
| 参考 → MINCO | **弯中 中位/最大** | **0.497 / 0.660 m** | 切弯在 MINCO 这一层 |
| MINCO → MPC | 终点距轨迹 | 0.00~0.01 m | 控制层没引入偏差 |
| 实际 → 参考 | 中位/最大 | 0.01 / 0.23 m | 跟踪正常 |

一句话：**看直道看平滑层的净空，看弯道看"参考→MINCO"的横向偏离**。

## 1. 直道贴边：SFC 走廊收缩 0.0 → 0.40

- **机理**：`SfcSquare` 给每个路径点建一个自由方块，方块半边取"到最近障碍的距离"。
  `corridor_shrink = 0` 时方块贴满障碍，MinimumSnap 在方块内**只最小化 jerk**，
  直道上没有任何横向约束 → 路径保持 A* 折线原本在走廊里的横向位置：
  A* 偏右，平滑后就一路偏右。
- **实测（同目标 A/B，只改这一项）**：
  - 直道平滑路径 中位净空 0.88 → **1.13 m**，偏心 0.40 → **0.20 m**；
  - `/plan` → `/plan_smoothed` 最大偏移 0.555 → **0.038 m**（平滑几乎不再改几何）；
  - 两次运行都 SUCCEEDED，0 abort；弯道切弯量不变（这条不该它管）。
- **代价 / 边界**：收缩越大，窄通道里可行方块越少。0.8 m 通道能拿到的最大净空是
  0.40 m，`shrink = 0.40` 时软目标仍可达；若现场出现"净空 0.37x 判死"，
  先回 0.30，而不是继续加。
- **配置**：`minimum_snap_smoother.corridor_shrink: 0.40`（实车/仿真/生成器三处同步）。

## 2. 拐弯切内道：MINCO 缺参考吸引项

- **机理**：优化目标是 jerk + 时间 + 障碍 + 速度/加速度罚。**没有"贴近参考"这一项**
  时，时间项会把轨迹往"更短"的内侧拉；障碍项只在接近安全距离时才激活，
  宽走廊里根本不构成约束 —— 所以**弯越宽，切得越狠**。
- 参考工程 `navi_minco_bit` 里有 `penalty_weight_att = 100`（内部路标点向参考折线吸引），
  本仓库的 `w_reference` 一直是写死的 0：只声明了配置项，从未实现读取。
- **实测（同目标，只改这一项）**：

  | | 弯中偏离 中位 / 最大 | 均值速度 | 最小净空 | 耗时 |
  | --- | --- | --- | --- | --- |
  | `w_reference = 0` | **0.497 / 0.660 m** | 1.61 m/s | 0.38 m | 16.9 s |
  | `w_reference = 100` | **0.053 / 0.195 m** | **1.76 m/s** | **0.46 m** | 15.8 s |

  改善近一个数量级，而且**跑得更快、停得更少**——不是用"慢"换来的：
  贴参考走比"切内道 + 反复重规划"更省时间。

## 3. 顺带修掉的两个同源问题

### 3.1 转角降速：从"假开关"变成真的安全网

- 参考工程在**稀疏折线**的顶点上量转角，按 `calCurvatureDecay` 求局部速度上限。
  本项目的输入是**平滑后的密集路径**：重采样 0.1 m 时逐点夹角只有 1° 量级，
  旧参数 `corner_speed_ratio`（线性插值）算出的比例恒接近 1.0 —— 改了这个参数
  完全没反应，是典型的"看着能调的假开关"。
- 处置：改用**弦长窗口**（前后各半窗的弦夹角）代替顶点角，衰减式与参考工程逐字一致
  （`v = min_vel + (v_max - min_vel)·exp(-ratio·decay_power)`）；
  地板用**比例**写法 `min_turn_vel_ratio = 0.23`（≈ 参考的 0.7/3.0），换速度档不用改；
  逐段速度上限（可达化制动传播后）再交给优化器当软约束阈值。
- 实测：长路线 94 m 里 38/88 帧量到 >5.7° 的转角，32/88 帧有段被限速；
  53° 弯处上限降到 **1.09 m/s**、指令速度确实跟到 1.1~1.6 m/s；缓弯不降。
  单独开它不改善几何（0.456 vs 0.497），**它是急弯的安全网，不是切弯的解**。

### 3.2 视野 3 → 6 m

- `planning_horizon` 对齐参考工程的 `lookahead_dist = 6.0`：2.6 m/s 档约 2.3 s 视野，
  弯道提前进视野、被转角降速覆盖。
- 与 `w_reference` 同用效果最好：弯中 0.044/0.122 m、净空 0.47 m、耗时与基线持平。

## 5. 下次怎么在 10 分钟内判读

1. **录包**：`./scripts/bringup/record_nav_bag.sh`（默认 14 路，含四层轨迹 + 诊断）。
2. **三条判据**，按顺序看，第一条不成立就别看后面：
   - 参考 vs 平滑路径 ≈ 0 → 裁剪/净空预推没有改几何；
   - 参考 vs MINCO：直道 < 0.05 m、弯中 < 0.2 m → 超了就是权重/参考项问题
     （先看 `w_reference` 是否真被读到，再看 `w_obstacle` 与 `w_time` 的量纲）；
   - MINCO vs 实际：p90 < 0.1 m → 跟踪没问题，别在 MPC 上调。
3. **诊断键**（`FollowPath/diagnostics` 与 `planning/diagnostics`）：
   `minimum_clearance`、`maximum_speed`、`corner_angle_max_deg`、
   `corner_speed_limit_min`、`corner_limited_pieces`。
   最后三个就是"转角降速到底有没有生效"的判据：角度为 0 说明这条参考上根本没有弯，
   上限等于 v_max 说明没被限速。
4. **常见误判**：
   - 把平滑层的偏移当成"MINCO 切弯"（两者相差一个数量级，混在一起就找错层）；
   - 统计"实际 vs 参考"时没排除换目标那几帧（参考会跳到新目标上，偏差虚高）；
   - 只对比包里的单帧：平滑/参考是静态的，MINCO/实际是逐帧的，要按时间对齐再比。

## 7. 经验

- **贴边与切弯不在同一层**：直道居中靠"走廊约束"，弯道贴线靠"参考吸引"，两者都不在控制层。
- **软约束替代不了参考项**：障碍项在宽走廊里根本不激活，时间项就会替它决定几何。
- **参数要有"是否生效"的判据**：`corner_speed_ratio` 改了没反应，是因为它的输入
  （逐点夹角）在这套链路上恒为 1° 量级；凡是新增可调参数，都要在诊断里输出它算出来的量。
- **先分层再调参**：四层轨迹都录下来，先用"哪一层开始偏"定位，再决定改哪一层。
